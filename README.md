# CSV Dataset Validator

Валидатор CSV и pandas DataFrame для датасетов cveta2 и clearml-yolo на основе Pandera.
Возвращает очищенные данные, отклонённые строки и все причины отклонения.
Неизвестные столбцы сохраняются с предупреждением.

## Установка

Python 3.10 или новее. Для работы из репозитория:

```bash
uv sync --dev
uv run csv-dataset-validator --help
```

Проверка файлов изображений необязательна:

```bash
uv sync --dev --extra images
```

Для установки библиотеки в другое окружение: `uv pip install .` или
`uv pip install '.[images]'`. Зависимостей от cveta2, ClearML и Ultralytics нет.

## Командная строка

```bash
uv run csv-dataset-validator dataset.csv --profile cveta2 --output-dir validation
uv run csv-dataset-validator dataset.csv --profile clearml-yolo \
  --check-images --output-dir validation
```

Профиль указывается явно. Результаты:

- `clean.csv` — исходные строки, прошедшие проверку, со всеми исходными столбцами;
- `broken.csv` — отклонённые строки с позицией, кодами причин и пояснениями;
- `report.json` — полный отчёт, связанные строки, IoU, счётчики и список пропущенных проверок.

Имена служебных столбцов не заменяют исходные поля: при совпадении добавляется `_`,
а выбранные имена записываются в `report.json`. Позиции строк начинаются с нуля;
это номера записей данных, а не физические номера строк CSV с многострочными полями.
Без `--output-dir` команда только печатает сводку. Исходный файл не изменяется.

`--iou-threshold` задаёт порог IoU (по умолчанию `0.99`, диапазон `(0, 1]`).
`--image-root` задаёт корень для изображений без заполненного `image_path`.
Относительные пути отсчитываются от каталога CSV. Для перезаписи результатов
нужен `--overwrite`; перезапись входного CSV запрещена и с этим флагом.

Обычная очистка завершается кодом **0**, даже если отклонены все строки.
С `--fail-on-invalid` отклонённые данные дают код **1**.
Ошибка чтения, структуры CSV или записи результатов даёт код **2**.
CSV с корректным заголовком без записей допустим и сопровождается предупреждением.

## Python API

```python
from csv_dataset_validator import ValidationOptions, validate_csv

result = validate_csv(
    "dataset.csv",
    profile="cveta2",
    options=ValidationOptions(check_images=False),
)

clean = result.clean
broken = result.broken
for position in result.broken_row_positions:
    for issue in result.reasons_for(position):
        print(position, issue.code, issue.message, issue.related_rows)
```

Для уже загруженных данных:

```python
from csv_dataset_validator import validate_dataframe

result = validate_dataframe(frame, profile="clearml-yolo")
```

`validate_dataframe` сохраняет порядок, значения и индексы исходных строк, в том числе
повторяющиеся индексы. `clean_row_positions` и `broken_row_positions` связывают результат
с позициями входных записей. `issues` содержит ошибки и предупреждения;
`warnings` — только предупреждения без отклонения. `is_valid` описывает исходный набор,
а не факт успешного выполнения очистки. `reasons_for(position)` возвращает все причины
для записи, включая общие ошибки структуры.

`ValidationOptions(emit_warnings=False)` отключает Python-предупреждения, сохраняя их
в отчёте. При проверке DataFrame относительные пути разрешаются от `base_dir`,
по умолчанию — от текущего каталога. `schema_for(profile)` возвращает полную схему
Pandera для самостоятельной проверки полей; очистку и межстрочные проверки выполняет
`validate_dataframe`.

## Правила очистки

- Некорректная аннотация исключает **всё изображение в пределах задачи**.
  Исходные корректные строки этой группы получают причину `image_quarantined`.
- Дубликаты являются исключением: сохраняется первая допустимая запись, последующие
  отклоняются. Проверяются полное равенство строк со всеми дополнительными полями
  и **IoU ≥ 0.99 независимо от класса**.
- Для IoU используются абсолютные координаты XYXY без прибавления единицы.
  Поворот игнорируется с предупреждением. Уже отклонённая запись не подавляет следующие.
- Разные `task_id` одного изображения проверяются отдельно. Строки без ID задачи
  образуют отдельную группу того же изображения.
- Отрицательные, вырожденные и выходящие за известные границы рамки отклоняются.
  Рамки не обрезаются. Отсутствие размеров явно отмечается как непроверенная верхняя граница.
- Пустые изображения сохраняются только при явной корректной записи без аннотаций.
  Изображения с отклонёнными рамками не превращаются в отрицательные примеры.
- Профиль cveta2 сохраняет корректные записи `deleted`; это не обучающие примеры.
  Профиль clearml-yolo их отклоняет и требует заполненные `image_path` и `split`.

CSV читается без автоматического преобразования значений: метки `001`, `NA`, `None`
и `null` остаются строками. Пробелы не удаляются. Числовые значения интерпретируются
для проверок, но не заменяются в результате. Синтаксически повреждённый CSV вызывает
`DatasetInputError`; обычные некорректные записи возвращаются в отчёте без исключения.

При `check_images=True` библиотека читает только локальные изображения, проверяет
декодирование, размеры и соответствие размеров CSV, учитывая ориентацию JPEG EXIF 6/8.
URI не скачиваются. Без этой опции содержимое изображений не читается, пути нормализуются
лексически; символьные ссылки разрешаются при включённой проверке файлов.

Все данные обрабатываются в памяти; потоковый режим не предусмотрен. Временная память
IoU ограничена одной группой, но время сравнения в группе в худшем случае квадратичное.
В дополнительных полях DataFrame поддерживается сравнение списков, словарей, массивов,
двоичных буферов и таблиц pandas. Для непрозрачных пользовательских объектов или циклических
структур точное сравнение строки пропускается с отдельным предупреждением; проверка IoU
продолжается. Значения не заменяются строковым представлением для сравнения.
Успешная проверка формата не гарантирует готовность к обучению: наличие необходимых
выборок, классов и другие требования остаются ответственностью вызывающей библиотеки.
